# 因材網物理九步驟架構檢核

## Overview

檢查投影片是否形成可自學、可追溯且不超綱的概念路徑。九步驟是功能覆蓋，不等於固定九張或不可調整的順序。

開始前讀取：

- `../../../references/skill-runtime.md`
- `../../../data/rubrics/nine-step.json`
- `../../../references/stage5_curriculum_and_scope.md`

## Inputs

必需：

- PPTX、逐頁文字或投影片 Markdown
- 專案學習節點碼與單元名稱

建議：

- 適用課程、年級與預計自學時間
- 圖片頁面或渲染結果
- 既有審查意見

若只有 PPTX，先用 `scripts/extract_office_text.py` 取出逐頁文字與 notes；需判斷圖像時再渲染。不要把空白 notes 當成內容缺失以外的物理問題。

## Workflow

1. 解析官方父碼，讀取課綱 statement 與 teaching_note。解析失敗即 `HOLD`。
2. 建立逐頁內容清冊：標題、正文、圖表、互動、notes、評量與可見來源。
3. 對 S1–S9 分別找「可指認證據」，標示完整、部分、缺失或不適用待確認。
4. 檢查概念鏈：目標 → 核心概念 → 學生語言 → 專家語言 → 證據 → 探究 → 應用。
5. 檢查每個已覆蓋步驟的品質；有標題但沒有功能證據仍算部分。
6. 先提出最小改造：保留、合併、補頁、重寫、重排、刪除。避免為湊九格增加重複頁。
7. 檢查新增內容的課綱範圍與前後銜接。
8. 同時列出已做好的設計與缺失，給出 `PASS`、`REVISE` 或 `HOLD`。

## Output contract

輸出依序包含：

1. **範圍卡**：專案碼、官方父碼、必修／選修、官方頁碼、限制摘要。
2. **九步驟覆蓋矩陣**：步驟、頁碼證據、品質、狀態、理由。
3. **概念銜接圖**：用一行箭頭或 Mermaid 顯示目前路徑與斷點。
4. **逐頁修訂清單**：原頁碼、動作、具體內容、優先級、影響步驟。
5. **新增頁草稿**：只為真正缺口提供標題、學生任務、核心內容與 notes。
6. **確認通過項目**：可保留的頁面與理由。
7. **總判定**：`PASS`、`REVISE` 或 `HOLD`，並列阻擋上架項目。

嚴重度使用 blocker、major、minor、suggestion。每項判定都要引用頁碼或輸入片段。

## Stop conditions

輸出 `HOLD` 而不是猜測：

- 無法解析官方父碼或課程層級。
- PPTX 只有圖片且尚未渲染／OCR，無法辨識主要內容。
- 缺少必要頁面或檔案損壞。
- 課綱、團隊規準與使用者要求互相衝突。

## Common mistakes

| 錯誤 | 修正 |
|---|---|
| 有九個標題就判定完整 | 檢查每一步是否真的完成教學功能 |
| 強迫一個步驟一張 | 允許一頁多功能或多頁完成一功能 |
| 只記缺失 | 同時記錄可保留的強項，避免過度改寫 |
| 未看圖就判圖文一致 | 標 `HOLD` 並要求渲染證據 |
| 用舊教材慣例覆蓋課綱 | A 級官方證據優先 |

## Example

使用者：「請檢查 `PEb-Vc-4-1` 牛頓第一定律簡報。」

先把它解析為 `PEb-Vc-4`，指出官方說明以定律意義為主、不涉及公式推導與計算；若簡報直接用 $F=ma$ 做大量代算，列為範圍 major finding，而不是因為有「核心原理」頁就算通過。
