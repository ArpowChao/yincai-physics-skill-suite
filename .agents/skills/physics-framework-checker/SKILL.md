# 因材網物理內容型 PPT 總審查

本 Skill 審查的是跨頁內容型 PPT。不要同時套用全域或舊版
`physics-framework-9step`；後者用於一頁式九宮格架構，不能要求內容型 PPT
顯性列出九格、學習目標句或大概念標題。

## Overview

檢查投影片是否真正把架構教出來，而不只形式上出現九個元素。九步驟負責功能
覆蓋；逐頁教學鏈負責確認問題、證據、推理、學生輸出、回饋與遷移能否連起來。
先審查並提出最小修復，不默默修改來源 PPTX。

開始前讀取：

- `../../../references/skill-runtime.md`
- `../../../data/rubrics/nine-step.json`
- `../../../references/stage5_curriculum_and_scope.md`
- `../../../references/ppt-content-review.md`

## Inputs

必需：

- PPTX、逐頁文字或投影片 Markdown
- 專案學習節點碼與單元名稱

建議：

- 一頁式架構 PPT 或架構圖；未提供時，架構覆蓋標為 `N/A`
- 適用課程、年級與預計自學時間
- 逐頁渲染、實際播放 MP4、內嵌影片與動畫
- 既有審查意見
- 正解、選項設計意圖及不可修改範圍

若只有 PPTX，先用 `scripts/build_pptx_review_manifest.py` 建立逐頁文字、notes、
物件關係及媒體清冊。涉及圖像、動畫或影片時，以 PowerPoint 實際播放與逐頁渲染
為證據；只讀 XML 不足以判斷畫面是否正確。若只有文字抽取，相關項目標示
`not_observable` 或 `HOLD`。

## Workflow

1. 保留來源檔；除非使用者要求升級，不覆寫或直接編輯 PPTX。
2. 先以專案碼精確查詢專案節點目錄，再解析官方父碼或技高官方父層，讀取
   statement、teaching_note、課程版本、官方頁碼與來源衝突。兩者皆失敗即
   `HOLD`；若映射有衝突，只把受衝突影響的範圍欄位列為 `HOLD`。
3. 讀完所有投影片、notes、公式、選項、圖說、隱藏頁及圖片型頁面；媒體需實際
   播放或檢視關鍵影格。
4. 把單元名稱視為學習目標錨點，檢查內容、活動與評量是否對題；不要因未另列
   行為動詞式目標句扣分。從跨頁活動、問題、證據與應用反推大概念並列出證據，
   不要求投影片明列「大概念」。
5. 寫出唯一的中央教學任務與目前實際教學路徑；若不能由內容合理寫出，或與
   單元名稱不一致，標示主線不清。
6. 建立逐頁教學清冊：主要角色、問題／主張、學生行動、預期輸出、回饋、先備、
   下一頁連結、S1–S9 對應及斷點標籤。
7. 對 S1–S9 找可指認證據，標示 `complete`、`partial`、`insufficient`、
   `contradicted` 或 `N/A`。有標題但沒有教學功能仍算薄弱。
8. 依 `ppt-content-review.md` 檢查架構覆蓋、連貫性、內容充實度與教學可用性，
   並完成十項 0–3 評分。
9. 重新檢查物理敘述、數值、正解、選項、活動安全與圖文一致。媒體需說明觀看
   焦點、比較量、學生輸出及後續使用；沒有後續證據功能者只能算情境。
10. 套用 critical gates。科學錯誤、答案矛盾、核心原理缺漏、不安全活動或關鍵
   任務完全沒有輸出／回饋時，總判定不得 `PASS`。
11. 先用保留、移動、合併、縮短、重寫修復；必要時才新增頁面。檢查修復內容
    是否超綱並維持前後連貫。
12. 同時列出確認良好與需要修正之處，輸出 `PASS`、`REVISE` 或 `HOLD`。

## Output contract

輸出依序包含：

1. **直接結論**：狀態、檢查範圍、最強段落與最大缺口。
2. **範圍卡**：專案碼、官方父碼、必修／選修、官方頁碼與限制摘要。
3. **教學路徑**：目前路徑與建議路徑，標出移動、合併、補橋接或新增。
4. **最高優先修正**：最多五項，包含位置、斷點類型、影響與可直接採用的修改。
5. **架構—內容對照**與**九步驟覆蓋矩陣**。
6. **十項內容評分**：分數、頁碼證據、判斷與最小修正；另列 critical gates。
7. **逐頁教學清冊**：角色、學生輸出、回饋、前後連結及斷點標籤。
8. **物理、媒體與版面風險**：影片另列觀看焦點、比較量、輸出與後續用途。
9. **修復藍圖**：優先重用現有素材；新頁只為真正缺口提供內容與 notes 草稿。
10. **確認保留項目、判讀限制與總判定**。

同時產出符合 `data/schemas/ppt-review-result.schema.json` 的
`review-result.json`，供 `scripts/build_review_workbench.py` 顯示。嚴重度使用
blocker、major、minor、suggestion；finding 要引用頁碼與可見文字或物件。

## Stop conditions

輸出 `HOLD` 而不是猜測：

- 無法解析官方父碼、可追溯的技高節點映射或課程層級。
- PPTX 只有圖片且尚未渲染／OCR，無法辨識主要內容。
- 影片、動畫或外部連結是結論關鍵，但未能播放或取得可驗證畫面。
- 題目沒有可確認正解、條件不足，或公式與講稿互相衝突。
- 缺少必要頁面或檔案損壞。
- 課綱、團隊規準與使用者要求互相衝突。

## Common mistakes

| 錯誤 | 修正 |
|---|---|
| 有九個標題就判定完整 | 檢查每一步是否真的完成教學功能 |
| 強迫一個步驟一張 | 允許一頁多功能或多頁完成一功能 |
| 因未另列學習目標句而扣分 | 以單元名稱為目標錨點，檢查內容、活動與評量是否對題 |
| 因未明列大概念而判不足 | 從跨頁活動、問題、證據與應用反推並檢查一致性 |
| 頁數多就判定內容充實 | 檢查問題、證據、推理、輸出、回饋與遷移功能 |
| 有影片就算體驗或證據 | 確認觀看焦點、比較量、學生輸出及後續用途 |
| 活動或提問等於學生思考 | 明列可觀察輸出與判定回饋 |
| 先建議補很多新頁 | 先檢查能否移動、合併、縮短或重寫現有內容 |
| 只記缺失 | 同時記錄可保留的強項，避免過度改寫 |
| 未看圖就判圖文一致 | 標 `HOLD` 並要求渲染證據 |
| 用舊教材慣例覆蓋課綱 | A 級官方證據優先 |

## Example

使用者：「請檢查 `PEb-Vc-4-1` 牛頓第一定律簡報。」

先把它解析為 `PEb-Vc-4`，指出官方說明以定律意義為主、不涉及公式推導與計算；
若簡報直接用 $F=ma$ 做大量代算，列為範圍 major finding。接著逐頁確認慣性現象
是否產生可觀察輸出、學生語言如何橋接到合力概念，以及應用題是否真的使用同一
原理；不能因為有「核心原理」標題就算通過。
