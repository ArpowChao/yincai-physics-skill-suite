# 配音讀音來源與證據層級

這份文件說明 `prepare-tts-transcript` 的製作依據、資料如何產生，以及資料能證明
什麼。它不是「某個 TTS 一定會念錯」的清單。

## 四層證據

1. **官方臺灣讀音**：用教育部辭典或審音資料判斷教材希望呈現的讀音。
2. **候選讀音**：用辭典詞目、兩岸差異或 g2pW 找出值得檢查的詞；只能標成待確認。
3. **目標 TTS 實測**：用實際要上線的語音服務、聲音與完整句子試聽，確認它真的
   念錯。不同服務或版本可能有不同結果。
4. **已驗證替代**：把原詞換成同音異字後再次試聽，確認讀音正確且沒有破壞停頓、
   重音或相鄰文字，才能加入團隊共用的 `verified.json`。

因此，「臺灣與中國讀音不同」不等於「目標 TTS 念錯」；「g2pW 判出正確讀音」
也不等於已找到可用的同音字替代。

## 目前專案資料的角色

| 資料 | 用途 | 可否自動改稿 |
|---|---|---|
| `data/tts-pronunciation/verified.json` | 已由人確認、試聽成功的共用替代規則 | 可以 |
| `data/tts-pronunciation/moe-heteronyms.json` | 教育部詞目讀音與同音字草稿 | 不可以，先由老師確認 |
| 瀏覽器個人詞庫 | 某位老師或某個聲音的本機經驗 | 只在該使用者選擇後套用 |
| g2pW 結果 | 依整句上下文判斷多音字的第二意見 | 不可以 |
| 兩岸讀音差異 | 優先測試可能受中國讀音影響的詞 | 不可以 |

## 教育部 15,660 條候選如何產生

來源是臺灣教育部《重編國語辭典修訂本》，使用
[g0v/moedict-data](https://github.com/g0v/moedict-data) 提供的 JSON 格式資料。
產生程式為 `scripts/import_moe_tts_lexicon.py`。

目前程式人工列出 51 個常見多音字及可供配音測試的同音字，再從辭典選出：

- 長度為 2 到 8 字的詞目；
- 至少包含一個上述多音字；
- 注音音節數能和詞目字數對齊。

依這個版本的來源與條件共產生 **15,660 條候選**。這個數字是「可能需要檢查的
辭典詞目」，不是 15,660 個已知錯音，也不是 15,660 條可直接套用的修正。
同音字是專案產生的配音草稿，教育部只提供詞目與讀音。

## 兩岸讀音差異的調查快照

可參考 [中華語文知識庫的說明](https://www.chinese-linguipedia.org/about.html)，以及
[g0v/moedict-data-csld](https://github.com/g0v/moedict-data-csld) 整理的《兩岸詞典》、
臺灣《國語一字多音審訂表》和中國《普通話異讀詞審音表》。本專案曾針對
`moedict-data-csld` commit
`a1e91196f84cd2f3456570906191615f477278c8` 做過一次離線調查：

- CSV 共 101,686 筆資料列（不含標題）；
- 7,936 筆同時具有臺灣與中國讀音，原始字串不同者 7,934 筆；
- 限制為 2 到 6 個純漢字、音節可對齊，並排除只剩「一／不」變調差異後，得到
  5,075 個詞目；
- 這些詞目包含 1,140 種不重複的「字、臺灣讀音、中國讀音」對應；出現至少
  2 次者 549 種、至少 5 次者 210 種、至少 10 次者 103 種。

以上是專案的分析快照，不是來源單位公布的統計，也不是 TTS 錯誤率。資料包含
罕用詞、歷史讀音、輕聲與其他不適合直接做替代規則的差異。可優先檢查的例子有
「血、期、質、微、髮、擊、儲、檔、夾、菌、穴、究、偽、寂、擁、築、績、堤、
矽、酵」等，但每個詞仍須回到完整語境和目標聲音實測。

目前網頁使用 `scripts/import_cross_strait_tts_candidates.py` 重新正規化讀音、合併
重複詞目後，載入 5,061 條不重複候選；其中 4,882 條能產生完整同音字草稿。
草稿優先使用專案人工指定的常見同音字，其次從來源中選擇在臺灣或中國資料確實
具有目標音的替代字。依團隊在 2026-08-11 的批次確認，4,882 條完整草稿會在
網頁預設套用到配音稿；179 條不完整草稿仍維持原稿並等待人工確認。這是配音用的
批次套用政策，不是語意改寫或逐條試聽認證；候選仍保留紫色來源標示與「保留原稿」
選項，也不會改動正式逐字稿。

官方依據可再查：

- [臺灣教育部國語辭典公眾授權網](https://language.moe.gov.tw/001/Upload/Files/site_content/M0001/respub/index.html)
- [臺灣教育部《國語一字多音審訂表》PDF](https://language.moe.gov.tw/001/Upload/Files/wxiao89/a.pdf)
- [中國教育部《普通話異讀詞審音表》頁面](https://hudong.moe.gov.cn/jyb_sjzl/ziliao/A19/201001/t20100115_75598.html)

## g2pW 的用途與限制

[g2pW](https://github.com/GitYCC/g2pW) 是依上下文處理華語多音字的 G2P 模型；研究
方法見 [g2pW 論文](https://arxiv.org/abs/2203.10430)。它適合在 Agent 或本機環境中
分析「家長」與「長度」這類同一個字在不同語境的讀音。

g2pW 輸出的是讀音，不會觀察正在使用的線上 TTS，也不會自動證明「掌度」之類的
替代一定有效。模型結果必須先轉成候選同音字，再交由人對目標聲音試聽。模型及其
相依套件較大，所以不放進純靜態 GitHub Pages；靜態頁面只載入已確認規則與輕量
候選資料。

## 公式念法

公式口語化規則是本專案為教學配音撰寫的規則，不是教育部辭典或 g2pW 的內容。
簡單次方、四則運算與等號可先產生口語草稿；根號、分數、上下標、向量、矩陣、
分段函數及巢狀式必須保留原式並由老師確認語意與停頓。正式逐字稿仍保留原公式，
只有配音稿使用口語版本。

## 共用規則的升級條件

新增 `verified.json` 規則時，至少記錄：

- 原詞、完整測試句、希望的臺灣讀音與依據；
- 目標 TTS 服務、聲音或版本、測試日期與實際誤讀；
- 同音字替代及替代後的試聽結果；
- 適用語境、可能衝突與自動化測試。

若缺少任何一項，就留在候選層或個人詞庫，不升級成全團隊自動規則。
