# 物理單元教材包出貨品管

## Overview

把投影片、學習單、素養題視為同一學習歷程的三個證據來源。只有三份檔案都存在不代表形成教材包；必須檢查共同目標、分工與遞進。

開始前讀取：

- `../../../references/skill-runtime.md`
- `../../../data/rubrics/nine-step.json`
- `../../../data/rubrics/literacy-eight-criteria.json`
- `../../../data/terminology/physics-terms.json`

## Inputs

必需：

- 同單元的投影片、學習單、題目
- 專案學習節點碼與預定課程

建議：

- 架構圖、答案版、審查紀錄
- 上架檔名規範與平台限制
- 各組件版本與負責人

## Workflow

1. 以教材索引配對組件；解析三者的專案碼與共同官方父碼。
2. 檢查版本、檔名與缺件。歷史狀態標籤只作提示。
3. 各自摘要三份教材的目標、核心概念、術語、符號、證據、活動、答案與認知層次。
4. 建立跨組件追溯矩陣：目標在哪裡教、在哪裡練、在哪裡評。
5. 檢查概念與模型一致，並找出學習單或題目未教先用、重複抄寫或完全未評的內容。
6. 檢查難度遞進：投影片建立理解，學習單形成證據與推理，評量要求遷移；不是單純題數增加。
7. 檢查術語、符號、單位、圖示、正方向、答案與資料來源。
8. 先整合三個專項 Skill 的 blocker，再處理跨組件問題。
9. 建立出貨清單與品質紀錄；任何 blocker 存在即不得 `PASS`。

## Output contract

輸出：

1. **包件清冊**：檔名、版本、類型、專案碼、官方碼、狀態。
2. **目標追溯矩陣**：目標 × 投影片 × 學習單 × 題目。
3. **跨組件一致性矩陣**：概念、術語、符號、圖、數值、假設、來源。
4. **難度與認知遞進圖**。
5. **blocker／major／minor／suggestion 修訂清單**，指定應改哪一份。
6. **確認通過項目**。
7. **上架判定**：`PASS`、`REVISE` 或 `HOLD`。
8. **可寫入 JSONL 的品質紀錄草稿**。

## Stop conditions

- 三類核心組件任一缺失或版本無法辨識。
- 三者解析到不同官方父碼且未說明跨單元設計。
- 題目答案、圖像或 notes 無法取得。
- 授權、個資或來源狀態不明，可能不適合上架。

## Common mistakes

| 錯誤 | 修正 |
|---|---|
| 只比檔名與關鍵字 | 建立目標與概念的跨組件追溯 |
| 三份內容越像越一致 | 應有教、練、評的分工 |
| 題目難就代表遞進 | 檢查是否建立在已教概念與表徵上 |
| 專項報告通過就自動出貨 | 還要檢查跨組件矛盾 |
| 只列問題不列強項 | 保存穩定通過設計供下次沿用 |

## Example

投影片使用 $v_0$、學習單使用 $u$、題目使用 $v_1$ 表示初速，即使各自都能理解，單元包仍有一致性 finding。若題目還要求投影片未教的選修推導，則是更高優先級的範圍與遞進問題。
