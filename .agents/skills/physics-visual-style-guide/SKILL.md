# 物理視覺規範與示意圖

## Overview

生成可讀、物理正確、可編輯且跨教材一致的圖像。圖的首要功能是傳達模型、方向、變數與證據，不以裝飾取代準確性。

開始前讀取：

- `../../../references/skill-runtime.md`
- `../../../data/terminology/physics-terms.json`

## Inputs

必需：

- 圖像類型與要表達的物理關係
- 專案學習節點碼
- 輸出格式：SVG、Mermaid、p5.js、PNG 或投影片元件

建議：

- 尺寸、背景、投影片模板色彩
- 必須標示的向量、角度、節點、元件與數值
- 是否要求比例正確
- 黑白列印與色覺辨識需求

## Workflow

1. 解析官方父碼，確認圖中概念與符號深度。
2. 寫出圖像模型清單：物件、交互作用、方向、參考系、假設、非比例元素。
3. 先做物理檢核，再選視覺編碼。顏色不能是唯一辨識線索。
4. 使用一致類別：力紅、速度藍、加速度綠、場紫；若模板衝突，以可讀性和現有品牌為準並記錄變更。
5. 箭頭從作用點或適當幾何位置出發；標籤避免遮住線、交點與物體。
6. 受力圖只畫作用在所選物體上的力；電路圖使用標準元件；光路圖保留法線與方向；波形圖標明座標軸與單位。
7. 產生可編輯原始碼與預覽。需要點陣圖時保留 SVG 原稿。
8. 完成物理 QA、視覺 QA、黑白／色覺 QA 與圖文一致性 QA。

## Output contract

輸出：

- **圖像規格卡**：目的、官方碼、模型假設、尺寸、比例狀態。
- **符號與視覺圖例**。
- **可編輯原始碼**。
- **替代文字**：能讓看不到圖的學生理解關鍵關係。
- **QA 清單**：方向、作用物、符號、單位、對比、標籤、圖文一致。
- **待確認與總判定**。

SVG 要含 `viewBox`、可讀文字、明確 marker 定義與不依賴本機字型的合理 fallback。

## Stop conditions

- 物理情境沒有指定作用物、參考系或方向，導致多種圖都合理。
- 題幹與要求的圖互相矛盾。
- 使用者要求比例精確但未給必要尺寸或數值。
- 未看到教材正文，卻要求判定圖文一致。

## Common mistakes

| 錯誤 | 修正 |
|---|---|
| 受力圖畫入「運動方向力」 | 只畫真實交互作用力 |
| 所有箭頭同色且無標籤 | 顏色加線型加文字三重辨識 |
| 場線相交 | 重新檢查場方向與拓樸 |
| 光線折射方向與介質關係相反 | 標法線、折射率與入射方向後驗算 |
| 只有圖片沒有原稿 | 同步交付 SVG／程式碼與替代文字 |

## Example

畫斜面木塊受力圖前，先指定「木塊」為研究物體；只畫重力、正向力與實際存在的摩擦力。速度箭頭若需要，放在受力圖外或用不同圖例，不能把速度當成第四個力。
