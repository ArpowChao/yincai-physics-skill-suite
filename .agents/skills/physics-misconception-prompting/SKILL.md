# 物理迷思與診斷誘答

## Overview

把錯誤選項當成可辨識的學生模型，而不是湊數字。每個誘答必須有合理思維來源、與其他選項可區分，且回饋能推動下一步思考。

開始前讀取：

- `../../../references/skill-runtime.md`
- `../../../data/misconceptions/starter.json`
- `../../../data/terminology/physics-terms.json`

## Inputs

必需：

- 專案學習節點碼與核心概念
- 題幹或要診斷的學生表現

建議：

- 真實學生作答、訪談或教師觀察的去識別摘要
- 正解與預期推理
- 年級、課程與已學內容
- 現有選項及選項分布

## Workflow

1. 解析官方父碼，寫出正確概念、適用條件與學生應有推理。
2. 從 C 級真實作答優先找迷思；初始資料庫只能當候選，不當普遍事實。
3. 對每個候選迷思建立「觀察 → 隱含規則 → 錯誤預測 → 可區辨證據」。
4. 選擇彼此可區分、且適合本課程層級的 2–4 個診斷目標。
5. 將迷思轉成語法平行、長度相近、可信但不含額外錯誤的選項。
6. 檢查選項不能靠格式、長度、絕對詞或單位破綻排除。
7. 為每個錯誤選項寫漸進回饋：指出思考焦點 → 給反例／問題 → 重建概念。
8. 記錄資料來源與信心；未經真實學生驗證的項目標「候選」。

## Output contract

輸出：

- **正確概念與邊界**。
- **迷思模型表**：ID、學生可能說法、隱含規則、錯誤預測、來源、信心。
- **診斷題與選項**。
- **選項—迷思映射**與可區辨理由。
- **分層回饋**：最小提示、反思問題、完整澄清。
- **後續驗證建議**：要收集哪些作答或訪談證據。
- **總判定與待確認**。

## Stop conditions

- 只有錯誤答案，沒有足夠證據推斷學生思維。
- 多個選項同時對應相同迷思，無法區辨。
- 候選迷思涉及未教內容，學生可能只是缺先備知識。
- 題幹本身條件不足或有物理錯誤。

## Common mistakes

| 錯誤 | 修正 |
|---|---|
| 把計算失誤都稱迷思 | 區分概念模型、程序錯誤與粗心 |
| 誘答只是相近數字 | 對應可解釋的推理分岔 |
| 從選項直接診斷人格或能力 | 只推論本題可支持的概念狀態 |
| 回饋直接公布答案 | 先給能讓學生自我修正的提示 |
| 把初始迷思庫當普遍真相 | 用在地學生資料驗證與更新 |

## Example

學生選「上拋球在最高點合力為零」可能源於「瞬間靜止就沒有受力」。診斷回饋先問：「如果重力在最高點消失，球接下來為何會落下？」再引導區分速度為零與加速度為零。
