# 因材網高中物理教材產線 Skill Suite 設計

**日期：** 2026-07-27
**狀態：** 已依現有 10 個 Skill、官方課綱 PDF、`資料/` 教材庫與外部 LLM-wiki 物理知識庫盤點結果定案

## 1. 目標與邊界

本專案把投影片、學習單、素養題三條線整合為可攜式 Skill Suite，目的不是一次性產出更多內容，而是讓老師用同一套證據、術語與審查門檻完成「設計 → 生成 → 審查 → 修訂 → 出貨」。十個 Skill 保持任務單一：架構、架構圖、講稿、學習單、素養題、圖像、審題、舊簡報升級、迷思誘答、單元包總檢。共用規則不得複製進十份 Skill，以免日後互相矛盾。

適用主體為十二年國教自然科學領域第五學習階段物理。官方課綱中的 `Ⅴc`（必修）與 `Ⅴa`（加深加廣選修）是範圍判定依據；教材檔名中的延伸碼（例如 `PKa-Vc-1-1-1`）是專案節點碼，不得誤認為官方課綱碼。系統遇到無法由官方來源確認的內容時，必須標示「待人工確認」，不得自行宣稱合格。

原始 PPTX、DOCX、PDF 與可能有授權限制的 LLM-wiki 內容只作本機資料來源，不預設納入公開 repo。Repo 收錄 Skill、可重跑腳本、結構化規準、來源索引與去識別化品質紀錄。這可兼顧可移植性、版權與教師個資風險。

## 2. 架構選擇

曾考慮三種做法：

1. **每個 Skill 各自帶完整資料庫**：單獨安裝方便，但規則會重複、更新成本高，容易產生十種課綱版本。
2. **所有功能合併成單一巨型 Skill**：共用資料容易，但觸發不精準、上下文過大，老師難以理解輸出責任。
3. **薄 Skill + 共用核心（採用）**：十個 Skill 僅保留流程與輸出契約；課綱、九步驟、評分規準、術語與品質紀錄集中管理。

採用方案的目錄責任如下：

- `.agents/skills/`：十個可被 Codex 發現的 Skill；每個含 `SKILL.md`、必要的 `references/` 導航與 `agents/openai.yaml`。
- `data/`：機器可讀的課綱、九步驟、八準則、術語、迷思與 schema。
- `references/`：供人與 AI 閱讀的證據摘要、資料來源政策與使用指南。
- `scripts/`：索引教材、解析課綱代碼、抽取 Office 文字、建立審查紀錄、彙整品質表現、驗證整套 Skill。
- `quality/`：缺失、通過項目、待確認事項與回歸案例；不存放學生個資。
- `tests/`：先失敗再實作的結構、解析、索引與端到端測試。

所有路徑由 repo 根目錄、設定檔或環境變數解析，禁止寫死磁碟代號。

## 3. 證據與資料流

資料分成四個信任層級：

1. **A 級：官方規範**——教育部課綱 PDF 及其頁碼。範圍判定與學習內容說明以此為準。
2. **B 級：經審定專案規準**——九步驟定義、春煌博士三面向八準則、團隊正式模板。每次修改需留下版本與決策紀錄。
3. **C 級：教師教材與已通過案例**——可作寫法、活動與常見缺失參考；檔名含「已」不等於已通過所有新規準。
4. **D 級：LLM-wiki 與 AI 推論**——作概念候選、公式領域與搜尋入口；使用前必須檢查來源、適用層級與課綱邊界。

每次任務先解析學習內容代碼，再取得官方父碼與層級，接著讀取九步驟／八準則等任務規準，最後才檢索舊教材與 LLM-wiki。生成或審查結果須記錄：輸入雜湊或檔名、Skill 版本、規準版本、使用證據、通過項目、缺失、嚴重度、修訂動作與人工決策。敏感內容只保留本機路徑或雜湊，不進公開紀錄。

## 4. 九步驟與三條產線

九步驟是共同教學骨架，不要求每一步恰好一張投影片，也不應機械地強迫順序。審查需同時判斷「覆蓋、品質、證據、銜接」：

1. 主題與學習目標
2. 大概念
3. 核心原理
4. 專家語言
5. 學生觀察語言
6. 體驗／現象
7. 證據與事實
8. 探究
9. 有感應用

投影片線建立概念主幹與自學導引；學習單線承接觀察、數據、推理與遷移；素養題線驗證學生能否在必要情境中使用概念。總檢不是只比對檔名，而是檢查三者的官方父碼、學習目標、核心命題、術語、符號、假設、認知層次與難度遞進是否一致。

自動化只處理可確定的工作：檔案盤點、代碼解析、組件配對、文字抽取、規則驗證與報告骨架。物理正確性、活動可行性、情境真實性與教學品質仍需 AI 提供證據化判斷，並保留教師最後決策權。

## 5. 失敗處理與品質閉環

系統採三種判定：`PASS`、`REVISE`、`HOLD`。`HOLD` 用於缺官方對照、來源互相衝突、圖像無法辨識、資料不足或涉及安全／實驗風險；禁止為了完成報告而猜測。嚴重度分為阻擋上架、重大、一般、建議四級。阻擋上架包含超綱、物理錯誤、正解不唯一、關鍵組件缺失、個資或授權風險。

品質紀錄同時保留正向表現與缺失。只記問題會讓 Skill 不斷增加限制；只記成功會掩蓋失敗模式。彙整腳本定期輸出高頻缺失、穩定通過項目、待人工決策與回歸案例。規則更新必須附一個能重現問題的案例，並重新跑全套驗證。

驗收包含：十個 Skill 結構檢查、無絕對路徑、所有引用存在、官方課綱碼解析、教材索引可重跑、Office 抽取可處理樣本、品質紀錄符合 schema，以及至少一組投影片／學習單／題目端到端 dry run。由於目前執行政策不允許自行派出子代理，Skill 的獨立代理壓力測試列為後續人工啟動項目；本輪以靜態規則、真實檔案與回歸測試補足。
